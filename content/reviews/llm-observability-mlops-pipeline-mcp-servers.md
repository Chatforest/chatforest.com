LLM observability and MLOps pipeline MCP servers address the operational layer of AI development — once you've built your models and agents, how do you **monitor** their behavior, **manage** your prompts, **orchestrate** training pipelines, and **analyze** experiment results? These servers bring that operational data into your AI assistant, so you can debug a failing trace, query experiment metrics, or trigger a pipeline run through natural language instead of switching between dashboards.

This is a distinct concern from model serving and inference (covered in our [AI/ML Model Serving review](/reviews/ai-ml-model-serving-mcp-servers/)). Where that review covers running models, this one covers **watching them run** — traces, metrics, prompts, pipelines, and experiments. For evaluation and benchmarking frameworks, see our [LLM Evaluation & Benchmarking review](/reviews/llm-evaluation-benchmarking-mcp-servers/). For agent coordination, see our [Agent Orchestration review](/reviews/agent-orchestration-mcp-servers/).

**Datadog MCP** (43 stars, OFFICIAL) is the **biggest new entrant** since our initial review. Datadog [launched its managed remote MCP server in March 2026](https://www.datadoghq.com/about/latest-news/press-releases/datadog-launches-mcp-server/) (GA announced March 9, 2026), now generally available. No local server needed — it connects directly to Datadog's cloud at `mcp.datadoghq.com`. The server ships with **16+ core tools** plus optional toolsets for **APM**, **Error Tracking**, **Feature Flags**, **DBM**, **Security**, and critically **LLM Observability**. The LLM Observability toolset provides tools for searching and analyzing LLM traces, inspecting span details, and evaluating experiment results — all accessible from Claude Code, Cursor, VS Code, OpenAI Codex CLI, and GitHub Copilot. For teams already running Datadog, this is the most natural path to AI-assisted observability — your LLM traces live alongside your infrastructure metrics in one platform, accessible through one MCP server.

**Arize Phoenix MCP** is a **major addition** to the category. Phoenix ([11,100+ stars](https://github.com/Arize-ai/phoenix)) — a widely-used AI observability platform — now ships a [remote MCP server built directly into the Phoenix server at `/mcp`](https://arize.com/docs/phoenix/integrations/phoenix-mcp-server), with the older standalone [`@arizeai/phoenix-mcp` npm package](https://www.npmjs.com/package/@arizeai/phoenix-mcp) (now v4.3.3) kept in maintenance mode for Phoenix instances that don't yet serve `/mcp`. Approximately **30 tools across 8 categories**: **Prompts** (10 tools — list, retrieve, version management, tagging, upsert), **Projects** (2 tools), **Traces** (2 tools), **Spans & Annotations** (2 tools), **Sessions** (2 tools), **Annotation Configs** (1 tool), **Datasets** (5 tools — management and example synthesis), and **Experiments** (2 tools). The prompt management suite alone — 10 tools — is more comprehensive than Langfuse's dedicated prompt server. Phoenix supports self-hosted deployment via Docker/Kubernetes or Arize's cloud at app.phoenix.arize.com. For teams wanting full MCP integration with a mature observability platform, this is now the strongest option. **Correction (2026-08-15 audit):** this section previously called Phoenix "the leading open-source AI observability platform" under an Apache 2.0 license and described the integration as the `@arizeai/phoenix-mcp` npm package alone. Phoenix's own [LICENSE file](https://github.com/Arize-ai/phoenix/blob/main/LICENSE) is actually the **Elastic License 2.0 (ELv2)** — a source-available license, not OSI-approved open source, since it restricts offering Phoenix as a competing hosted service — and Arize's docs confirm the standalone npm server is now superseded by the built-in remote MCP. Both points are corrected above.

**Opik MCP** (218 stars) remains a solid modular observability server. Built by the Comet team, it provides unified access to the open-source Opik platform through modular toolsets: **core**, **integration**, **expert-prompts**, **expert-datasets**, **expert-trace-actions**, **expert-project-actions**, and **metrics**. Supports both local stdio and remote streamable-http transports. Recent platform additions include **prompt version tags** for labeling prompt versions, and **OpenClaw integration** (opik-openclaw plugin) providing full-stack observability for agents. **Correction (2026-08-15 audit):** this section previously said development had slowed and the MCP server hadn't seen commits since March 7 — [the repo's commit history](https://github.com/comet-ml/opik-mcp/commits/main) shows active development through at least August 14, 2026, so that claim is removed.

**LangSmith MCP** (131 stars, up from 89) was the official standalone MCP server from the LangChain team, providing 16 tools across 6 categories covering conversation thread history, prompt management, trace and run analysis, dataset management, experiment execution, and billing usage. **Correction (2026-08-15 audit):** the [langchain-ai/langsmith-mcp-server repo](https://github.com/langchain-ai/langsmith-mcp-server) was **archived (read-only) by its owner on August 14, 2026** — the day before this audit. LangChain's own docs confirm the successor: [LangSmith now runs an OAuth-authenticated remote MCP server directly on LangSmith Cloud](https://docs.langchain.com/langsmith/langsmith-mcp-server) (and on self-hosted LangSmith v0.15+), announced May 9, 2026, so no local server or API key is required. Teams on LangSmith Cloud or v0.15+ should use the hosted remote MCP; the archived standalone repo remains usable as reference but will receive no further updates. The trade-off remains: deeply integrated with the LangChain ecosystem, less useful if you use other frameworks.

**Helicone MCP** ([v0.1.6](https://www.npmjs.com/package/@helicone/mcp), up from initial release) provides a different angle — it's both an observability query tool and an LLM proxy. **Correction (2026-08-15 audit):** the [helicone-mcp source](https://github.com/Helicone/helicone/tree/main/helicone-mcp) now lists **three** tools, not two as previously stated: `use_ai_gateway` (make LLM requests through Helicone's AI Gateway with automatic observability, 100+ models in OpenAI SDK format), `query_requests` (search request logs with filters, pagination, sorting), and `query_sessions` (search sessions with time range filtering). Available via `npx @helicone/mcp@latest`.

## Distributed Tracing & Debugging (1 server)

| Server | Stars | Language | License | Tools | Key Feature |
|--------|-------|----------|---------|-------|-------------|
| [traceloop/opentelemetry-mcp-server](https://github.com/traceloop/opentelemetry-mcp-server) | 198 | Python | Apache 2.0 | 10 | Cross-backend OTel trace querying |

**OpenTelemetry MCP Server** (198 stars, up from 175) remains the only MCP server that provides a **vendor-neutral** view into your distributed traces. It connects to three backends — **Jaeger**, **Grafana Tempo**, and **Traceloop** — through a unified interface. Ten tools cover the essential debugging workflow: `search_traces` and `search_spans` for finding relevant data, `get_trace` for complete trace details, `find_errors` for error discovery, and a suite of LLM-specific tools: `get_llm_usage`, `list_llm_models`, `get_llm_model_stats`, `get_llm_expensive_traces`, and `get_llm_slow_traces`. The LLM-specific tools use OpenLLMetry semantic conventions. v0.2.2 is the latest release, with recent updates focused on security dependency fixes. Requires Python 3.11+, distributed via PyPI as `opentelemetry-mcp`. The vendor-neutral approach remains the key differentiator — particularly relevant now that Datadog's MCP server offers a proprietary alternative for teams already in that ecosystem.

**Langfuse MCP (official)** (173 stars, up from 158) focuses on prompt management through the MCP Prompts specification. Four tools for listing, retrieving, creating, and updating prompts. Built directly into Langfuse at `/api/public/mcp` using streamableHttp transport — no separate server to deploy. **Major news: [Langfuse was acquired by ClickHouse](https://clickhouse.com/blog/clickhouse-raises-400-million-series-d-acquires-langfuse-launches-postgres) in January 2026** as part of ClickHouse's $400M Series D. Langfuse had already migrated its data layer to ClickHouse for v3, making the acquisition a natural fit. The platform remains MIT open source and self-hostable — ClickHouse has committed to no licensing changes. With [33K+ GitHub stars](https://github.com/langfuse/langfuse) and, per [ClickHouse's acquisition announcement](https://clickhouse.com/blog/clickhouse-raises-400-million-series-d-acquires-langfuse-launches-postgres), 26M+ SDK installs/month and adoption by 19 of the Fortune 50 as of the January 2026 announcement, Langfuse now has enterprise-grade backing. **Correction (2026-08-15 audit):** this section previously cited "30K+" stars and "50M+" SDK installs/month, but the linked source only supports 26M+ installs/month, and the live repo now shows 33K+ stars — both corrected above so the numbers match what the cited source (and the repo itself) actually say. The official MCP server itself has been dormant since early 2025.

**Langfuse MCP (community — avivsinai)** is a **major community alternative** that dramatically expands Langfuse MCP coverage. [avivsinai/langfuse-mcp](https://github.com/avivsinai/langfuse-mcp) (104 stars, [v0.10.1 on PyPI](https://pypi.org/project/langfuse-mcp/), Python, MIT) provides **48 tools across 11 categories**: Traces (2 tools), Observations (2), Routing (4), Sessions (3), Exceptions (4), Prompts (5), Datasets (11), Annotation Queues (10), Scores (2), Metrics (2), and Schema (1). **Correction (2026-08-15 audit):** the [live README](https://github.com/avivsinai/langfuse-mcp/blob/main/README.md) shows the server has grown well past the "37 tools across 8 categories" figure previously stated here, and is written in Python (not TypeScript as this page previously said) — both corrected above. Where the official Langfuse MCP only exposes prompt management, this community server provides the **full Langfuse observability surface** — trace debugging, session analysis, exception tracking, dataset management, and annotation workflows. Selective tool loading lets you enable only the categories you need. For teams using Langfuse as their primary LLM observability platform, this is the MCP server to use.

**Braintrust MCP** — **Correction (2026-08-15 audit):** this section previously described Braintrust's MCP integration as the `@braintrust/mcp-server` npm package (v0.0.3, 7 tools). That package is now a [deprecated stdio compatibility shim](https://www.npmjs.com/package/@braintrust/mcp-server) (latest npm version 0.0.5, published June 2026); Braintrust has moved to a **hosted remote MCP server** at [`https://api.braintrust.dev/mcp`](https://www.braintrust.dev/docs/integrations/developer-tools/mcp) (EU: `api-eu.braintrust.dev/mcp`), authenticated via OAuth against your Braintrust account — no local install needed. The hosted server exposes roughly ten tools, including `search_docs` (search Braintrust documentation), `resolve_object` (look up specific objects), `list_recent_objects` (browse recent items), `infer_schema` (discover data structure), `search_patterns`/`new_pattern`/`update_pattern` (track project patterns), `sql_query` (query experiments and logs with SQL), `summarize_experiment` (experiment analysis), and `generate_permalink` (shareable links). The SQL query tool remains the standout — it enables ad-hoc analysis of production logs and experiment data directly from your IDE. Braintrust itself provides versioned prompt management, evaluation, and observability, so the MCP server gives IDE-based access to the full platform.

**W&B MCP** (68 stars, up from 41) has seen the **most dramatic expansion** in this category. The server grew from 6 tools to **20 tools** with v0.3.2 (April 2026), adding substantial new capabilities:

- **Weave trace analysis** — `infer_trace_schema_tool`, `query_weave_traces_tool`, `count_weave_traces_tool` for LLM trace inspection with detail-level control
- **Model registry** — `list_registries_tool`, `list_registry_collections_tool`, `list_artifact_versions_tool`, `get_artifact_details_tool`, `compare_artifact_versions_tool` for artifact and model version management
- **Enhanced experiment tools** — `query_wandb_tool`, `get_run_history_tool`, `log_analysis_to_wandb`
- **Reporting** — `create_wandb_report_tool` for generating reports with markdown, charts, and panels
- **Documentation** — `search_wandb_docs_tool`

The model registry and artifact comparison tools are particularly valuable — you can now diff two model versions, trace their lineage, and inspect metadata without leaving your IDE. Recent commits also added Datadog pipeline integration and JSON log format for containerized deployments. This is no longer a "query experiments" server — it's a comprehensive W&B operations interface.

**MLflow built-in MCP** is a **major new addition** — MLflow (the most widely-used open-source ML platform) now ships an official MCP server built directly into the framework. Run it with `mlflow mcp run` (requires MLflow 3.5.1+, installable via `mlflow[mcp]`). Ten trace management tools: `search_traces`, `get_trace`, `delete_traces`, `set_trace_tag`, `delete_trace_tag`, `log_feedback`, `log_expectation`, `get_assessment`, `update_assessment`, and `delete_assessment`. Currently marked as experimental and focused on trace management rather than the full MLflow surface (experiments, runs, model registry). For teams already using MLflow for experiment tracking, this eliminates the need for third-party MCP servers for basic trace operations.

**MLflow MCP (kkruglik)** (14 stars, up from 3) **expanded dramatically** from 17+ tools across several releases since March:
- **v0.4.0** (April 22) — `get_experiment_tags`, `audit_mlflow_setup` prompt (evaluates deployment against best practices across 7 categories)
- **v0.3.0** (April 18) — 5 delete tools (`delete_run`, `delete_experiment`, `delete_model_alias`, `delete_model_version`, `delete_registered_model`), tool annotations with `readOnlyHint`, `idempotentHint`, and `destructiveHint`
- **v0.2.0** (April 17) — MLflow 3 LoggedModel support, write tools (register_model, set_model_alias, set tags), search_logged_models, search_experiments, get_parent_run, model registry tools

**Correction (2026-08-15 audit):** this section previously said the tool count reached 39. The [live README](https://raw.githubusercontent.com/kkruglik/mlflow-mcp/main/README.md) currently lists **37 tools** across 8 categories (Experiments 7, Runs 6, Metrics & Parameters 2, Artifacts 3, Analysis & Comparison 2, Logged Models 2, Model Registry 14, Health 1); corrected above and in the table.

This is now the most comprehensive MLflow MCP server by far — 37 tools vs. the official MLflow MCP's 10. If you need full experiment, run, artifact, and model registry access via MCP, this is the one to use.

**Comet MCP** (1 star, v1.4.1) added **asset tools and an extensible asset handler plugin system** in April 2026. Still maintained despite low adoption — the OTel instrumentation and asset plugin architecture suggest this is built for internal use at Comet/Opik as much as for external users.

## The Big Picture

LLM observability and MLOps pipeline MCP servers have **matured significantly** since our initial review. The arrival of Datadog's official MCP server, Arize Phoenix's built-in MCP, MLflow's official MCP integration, and W&B's tool expansion signal that **platform vendors now treat MCP as a standard integration surface**, not an experimental add-on. The category has grown from ~10 servers to 15+, with three major platforms (Datadog, Phoenix, MLflow) adding official MCP support within the same several-month window in early-to-mid 2026.

**Best in class:** Arize Phoenix MCP (~30 tools, source-available under Elastic License 2.0, self-hostable) is the most comprehensive option outside the fully commercial platforms. Datadog MCP (managed remote, 16+ tools + specialized toolsets) is the strongest commercial option. W&B MCP (20 tools, v0.3.2) has shown the most dramatic improvement.

**Most practical for teams already using the platform:** Choose based on what you already run. Datadog users get MCP with zero setup. Phoenix users get it built-in. LangChain teams should use LangSmith Cloud's hosted remote MCP (the standalone langsmith-mcp-server repo is now archived). MLflow teams now have an official option. Each server integrates deeply with its parent platform — that's the point.

**Unique value:** ZenML MCP remains the only server that can **trigger** ML pipeline runs. OpenTelemetry MCP is the only vendor-neutral tracing option. Helicone uniquely combines observability with LLM request routing. Braintrust MCP's SQL query tool enables ad-hoc log analysis.

**Key gaps (narrowing):** Datadog now provides cross-provider cost visibility within its platform, partially closing the cost analytics gap. But no unified server bridges observability, prompt management, and pipeline orchestration — you still need 2-3 separate MCP servers. Prompt management servers don't version-control through Git. Pipeline servers can trigger runs but can't stream real-time progress. No A/B test management for model deployments. The official MLflow MCP covers only traces, not the full experiment/model registry surface.

**Rating: 4/5** — The category has shifted from "promising but fragmented" to "enterprise-ready with clear leaders." Three major observability platforms (Datadog, Arize, Langfuse/ClickHouse) now have official MCP servers. W&B tripled its tool count. MLflow added built-in MCP support. The fragmentation concern remains — each server is still an island — but the islands are now substantial, well-maintained, and backed by well-funded companies. The gap between this category and more mature MCP categories has narrowed considerably.
