Agent orchestration is where the MCP ecosystem gets ambitious — and in early 2026, it exploded. Instead of a single AI assistant calling tools, these servers coordinate **multiple agents** working in parallel, route tasks to specialists, manage persistent work items across sessions, and bridge protocols so agents built on different frameworks can collaborate.

The ecosystem now splits into three philosophies: **workflow-centric** (define patterns like chain, parallel, router, and let the framework handle execution), **swarm-centric** (deploy fleets of specialized agents that coordinate autonomously), and a new entrant — **company-centric** (structure agents into organizational hierarchies with budgets, governance, and goal alignment). All three are well-represented, with Paperclip's continued growth (now [78K+ stars](https://github.com/paperclipai/paperclip)) and open-multi-agent's rapid emergence ([~6.8K stars](https://github.com/open-multi-agent/open-multi-agent) in weeks) signaling sustained demand for the organizational model.

**open-multi-agent/open-multi-agent emerged with ~6K stars, now [~6.8K](https://github.com/open-multi-agent/open-multi-agent).** Launched April 1, 2026 as JackChen-me/open-multi-agent, now moved to the open-multi-agent org. ## Agent Frameworks & Workflow Engines (3+ servers)

| Server | Stars | Language | License | Key Feature |
|--------|-------|----------|---------|-------------|
| [lastmile-ai/mcp-agent](https://github.com/lastmile-ai/mcp-agent) | ~8.5K | Python | Apache 2.0 | Composable Anthropic agent patterns + cloud runtime |
| [evalstate/fast-agent](https://github.com/evalstate/fast-agent) | ~3.9K | Python | Apache 2.0 | Chain/parallel/router + Agent Skills + ACP |
| [rinadelph/Agent-MCP](https://github.com/rinadelph/Agent-MCP) | 1.3K | Python/TS | AGPL-3.0 | Multi-agent parallel with knowledge graph |

**mcp-agent by LastMile AI** ([~8.5K stars](https://github.com/lastmile-ai/mcp-agent)) remains the most popular agent framework built on MCP. It implements Anthropic's ["Building Effective Agents"](https://www.anthropic.com/engineering/building-effective-agents) patterns as composable building blocks: **parallel** fan-out/fan-in, **orchestrator-worker** decomposition, **evaluator-optimizer** loops, **routers**, and **map-reduce** pipelines. Full MCP support covers tools, resources, prompts, notifications, OAuth, sampling, and elicitation. Multi-provider LLM integration works with OpenAI, Anthropic, Google, Azure, and Bedrock. Production features include Temporal-backed durable execution and structured output via Pydantic models. **Notable development status:** [minimal commits since January 25, 2026](https://github.com/lastmile-ai/mcp-agent/commits/main) — the two active feature branches (`feature/temporal_prime`, `feature/app_server`) point to a significant upcoming rewrite. Teams evaluating mcp-agent for production should watch those branches closely before committing.

**fast-agent** (now [~3.9K stars](https://github.com/evalstate/fast-agent)) has seen steady development. Workflow patterns include chain, parallel, evaluator-optimizer, and router. **Recent additions:** an [`/skills` command](https://fast-agent.ai/agents/skills/) for listing and managing installed [Agent Skills](https://fast-agent.ai/agents/skills/); an [`/connect` command](https://github.com/evalstate/fast-agent/blob/main/README.md) for connecting to MCP servers at runtime over stdio or streamable HTTP (with OAuth); and **[ACP (Agent Client Protocol)](https://zed.dev/acp/agent/fast-agent)** support via Zed Industries alongside MCP, letting fast-agent run as an agent inside Zed's editor. (Note: ACP here is Zed's *Agent Client Protocol*, not "Agent Communication Protocol" — the two are unrelated specs.)

**Agent-MCP** ([1.3K stars](https://github.com/rinadelph/Agent-MCP), 300 commits) focuses on the multi-agent coordination problem. Multiple specialized agents run in parallel on different project aspects, sharing context through a **persistent knowledge graph**. Real-time visualization shows agent status and communication patterns. Available in both Python (recommended) and TypeScript/Node.js implementations. **License: [AGPL-3.0](https://github.com/rinadelph/Agent-MCP/blob/main/LICENSE)** — important for commercial adoption decisions. The knowledge graph approach remains distinctive — agents don't just pass messages, they maintain shared project memory with RAG capabilities.

## Multi-Agent Swarm & Company Orchestration (4+ servers)

| Server | Stars | Language | License | Key Feature |
|--------|-------|----------|---------|-------------|
| [paperclipai/paperclip](https://github.com/paperclipai/paperclip) | ~78K | TypeScript | MIT | Company orchestration, CEO/Manager/Worker hierarchy, plugins |
| [ruvnet/ruflo](https://github.com/ruvnet/ruflo) | ~68K | TS/Rust/Python | MIT | ~314 MCP tools (v3.5.59), 16 agent roles, agent federation |
| [open-multi-agent/open-multi-agent](https://github.com/open-multi-agent/open-multi-agent) | ~6.8K | TypeScript | MIT | One runTeam() call, 3 dependencies, MCP via connectMCPTools() |

**Paperclip** (now [~78K stars](https://github.com/paperclipai/paperclip), up from 66K in May 2026 and 57K before that) continues its remarkable growth. Launched around March 2–4, 2026 by pseudonymous developer @dotta — GitHub shows the [repo created March 2, 2026](https://github.com/paperclipai/paperclip) — and [reportedly crossed 30K stars within three weeks](https://pub.towardsai.net/paperclip-the-open-source-operating-system-for-zero-human-companies-2c16f3f22182) ("launched on March 4, 2026 and crossed 30,000 GitHub stars within three weeks"; we could not locate a Paperclip-authored primary source for this specific figure, so it's attributed to contemporaneous reporting rather than stated as independently confirmed) and has since reached ~78K — among the fastest-growing projects in agent orchestration. The core idea: orchestrate AI agents the way you'd manage a company. A **CEO agent** receives top-level goals and decomposes them. **Manager agents** handle functional areas. **Worker agents** execute specific tasks. The Node.js server with React dashboard provides org charts, budgets, governance, goal alignment, and cost tracking. **New since April:** calendar-versioned daily releases (v2026.MMDD.patch pattern), an [expanded plugin host surface](https://github.com/paperclipai/paperclip/releases/tag/v2026.512.0) with CLI-scaffolded local plugin development and an `@paperclip/plugin-llm-wiki` package, **secrets provider vaults** with AWS Secrets Manager remote import, and **Cursor Cloud and ACPX local adapters**. Supports Claude Code, OpenClaw, Codex, Cursor, and bash-based agents. A separate community-built [MCP server](https://github.com/wizarck/paperclip-mcp) exposes Paperclip's REST API as MCP tools. [3,600+ commits](https://github.com/paperclipai/paperclip), MIT license.

**Ruflo** (now [~68K stars](https://github.com/ruvnet/ruflo), up from 48.2K in May 2026 and 32.6K before that — a **48% increase** in 27 days at the time) continues its remarkable growth trajectory. Was at v3.6.12 (May 1, 2026) as of that update; the [changelog](https://github.com/ruvnet/ruflo/blob/main/CHANGELOG.md) shows continued releases since. **Key upgrades since April:** [**agent federation**](https://github.com/ruvnet/ruflo) — multiple Ruflo instances on different machines communicate without data exposure, enabling true distributed swarm deployments; rewritten worker-to-worker communication protocol with lower latency and adaptive back-pressure; MCP tools reported at **[314 as of the v3.5.59 release](https://github.com/ruvnet/ruflo/releases/tag/v3.5.59)** ("Full Capability Verification: 314 MCP Tools, 38 CLI Commands, 22 Plugins"); [**16 defined agent roles**](https://github.com/ruvnet/ruflo/blob/main/CLAUDE.md) plus custom types; [**AgentDB v3 with 8 new controllers**](https://github.com/ruvnet/ruflo/issues/1228) (HierarchicalMemory, MemoryConsolidation, SemanticRouter, GNNService, RVFOptimizer, MutationGuard, AttestationLog, GuardedVectorBackend). Ruflo's own [SWE-Bench Evaluation wiki page](https://github.com/ruvnet/ruflo/wiki/SWE-Bench-Evaluation) and project materials claim an **84.8% SWE-bench solve rate** and up to **75% API cost savings** from its 3-tier model routing — both are self-reported by the project with no independent reproduction found, so treat them as vendor-claimed rather than verified benchmarks. The codebase now spans TypeScript, JavaScript, and Rust (a Rust/WASM policy engine and proof system were added in the v3.5 rewrite); we could not confirm a current precise language-percentage breakdown. Note: still retains `claude-flow` as the npm/CLI identifier due to historical naming — the [repository's own README states plainly "Claude Flow is now Ruflo"](https://github.com/ruvnet/ruflo), confirming the rebrand, though we could not pin down a primary source for the exact rename date or the reason (secondary sources describe it as a trademark-driven rename in January 2026, but we could not verify that against a project-authored source, so we're not stating it as fact here). The scope remains enormous; teams should evaluate which components they need.

**open-multi-agent** (now [~6.8K stars](https://github.com/open-multi-agent/open-multi-agent)) is a strong new entrant. Launched April 1, 2026 as JackChen-me/open-multi-agent, it has since moved to the open-multi-agent org. Core philosophy: maximum simplicity for multi-agent execution. A single `runTeam()` call takes a goal description and returns a DAG result after auto task decomposition and parallel execution across agents. Only **3 runtime dependencies**. MCP integration is explicit — call `connectMCPTools()` to give agents tool access. TypeScript-native. The minimalist API contrasts sharply with Paperclip and Ruflo's comprehensive platforms — teams wanting low-overhead multi-agent execution have a new option.

**AWS Labs' CLI Agent Orchestrator** (now [~1K stars](https://github.com/awslabs/cli-agent-orchestrator)) reached [**CAO 2.0**](https://github.com/awslabs/cli-agent-orchestrator/releases/tag/v2.0.0) (released March 26, 2026) — the most significant update since launch. At that release, CAO supported **7 agent providers**: Kiro CLI, Claude Code, Codex CLI, Gemini CLI, Kimi CLI, GitHub Copilot CLI, and Amazon Q Developer CLI. **New in CAO 2.0:** a **React-based Web UI dashboard** for browser-based session management with live status tracking; **scheduled flows** with cron-like automation; three distinct orchestration patterns — **handoff** (synchronous transfer), **assign** (asynchronous parallel), and **send message** (direct communication); cross-provider orchestration; and dependency-level security hardening, including a fix for [CVE-2026-25645](https://access.redhat.com/security/cve/cve-2026-25645) (a `requests` library flaw, patched via a dependency bump). Provider support keeps shifting fast — [v2.3.0 (July 2026)](https://github.com/awslabs/cli-agent-orchestrator/releases/tag/v2.3.0) already dropped Amazon Q CLI and Gemini CLI in favor of Cursor CLI and Antigravity CLI, so treat the exact provider list as a snapshot rather than a fixed feature. The broadened provider support still makes CAO one of the more vendor-neutral multi-agent coordinators in this category.

**Note:** [awslabs/multi-agent-orchestrator has been **rebranded Agent Squad**](https://github.com/2FastLabs/agent-squad) and moved to 2FastLabs/agent-squad — the original `awslabs/multi-agent-orchestrator` URL now redirects there. This is distinct from awslabs/cli-agent-orchestrator (CAO). Teams using the original AWS multi-agent-orchestrator library should track the new repository.

## Task & Work Item Orchestration (1+ servers)

| Server | Stars | Language | License | Tools | Key Feature |
|--------|-------|----------|---------|-------|-------------|
| [jpicklyk/task-orchestrator](https://github.com/jpicklyk/task-orchestrator) | ~200 | Kotlin | MIT | 14 | Persistent work item graph, quality gates, unified WorkItem model |

**jpicklyk/task-orchestrator** (now [~200 stars](https://github.com/jpicklyk/task-orchestrator)) went through a **ground-up v3 rewrite** with a unified `WorkItem` model replacing the previous task/subtask distinction, now **14 MCP tools** (up from 13 at v3.3.0) covering CRUD operations, notes, dependencies, and workflow progression, and dependency relation types (BLOCKS, IS_BLOCKED_BY, RELATES_TO). Work items progress through server-enforced phases: queue → work → review → terminal. Each transition has quality gates via phase-specific notes. The hierarchy supports epics, features, tasks, and subtasks. Workflow schemas definable in **YAML** set planning floors and enforce minimum specification requirements. [**Security model documentation**](https://github.com/jpicklyk/task-orchestrator/pull/118) published covering database-per-tenant isolation (separate database files per team/fleet, not schema-level multi-tenancy). Written in Kotlin (2.3.21 as of this update, was 2.2.0 in the earlier release). Claude Code integration includes skills and automation hooks.

**Note:** [EchoingVesper/mcp-task-orchestrator](https://github.com/EchoingVesper/mcp-task-orchestrator) (28 stars, v2.0.0) was **archived August 2025** and is no longer actively maintained. Teams needing role-based task orchestration should evaluate jpicklyk/task-orchestrator's workflow schema approach instead.

## CLI Workflow Orchestration (1 server)

| Server | Stars | Language | License | Key Feature |
|--------|-------|----------|---------|-------------|
| [microsoft/conductor](https://github.com/microsoft/conductor) | ~384 | — | MIT | YAML-declared deterministic multi-agent workflows |

**[microsoft/conductor](https://opensource.microsoft.com/blog/2026/05/14/conductor-deterministic-orchestration-for-multi-agent-ai-workflows/)** (announced May 14, 2026 on the Microsoft Open Source Blog) takes a deliberately deterministic approach to multi-agent workflows: the **workflow topology is declared in YAML, not discovered at runtime**. This contrasts with frameworks like Paperclip and Ruflo where agent routing emerges from LLM decisions. Conductor defines which agents handle which tasks, with explicit handoffs. Supports **GitHub Copilot** and **Anthropic Claude** as agent providers with per-agent model overrides; **MCP servers** give agents tool access. MIT license. At the time of the May 2026 update the project was newly released with star counts not yet established; it has since grown to [~384 stars](https://github.com/microsoft/conductor) — the Microsoft backing and explicit determinism model continue to attract teams that need reproducible, auditable agent workflows. Compare with awslabs/cli-agent-orchestrator (CAO) for multi-provider CLI orchestration and jpicklyk/task-orchestrator for work item-level control.

Positions itself as "a complete AI agent operating system." The "MIT+OpenAI/Anthropic Rider" license is worth reading carefully before enterprise adoption.

## Protocol Bridges — MCP ↔ A2A (1+ servers)

| Server | Stars | Language | License | Key Feature |
|--------|-------|----------|---------|-------------|
| [GongRzhe/A2A-MCP-Server](https://github.com/GongRzhe/A2A-MCP-Server) | 148 | Python | Apache 2.0 | Bridges MCP with Google's A2A protocol (archived) |

**A2A-MCP-Server** (148 stars) bridges two complementary protocols: **MCP** (how agents access tools) and **A2A** (how agents talk to each other). Google's [Agent-to-Agent protocol](https://github.com/a2aproject/A2A) enables communication between opaque agentic applications built on different frameworks. This server lets MCP-compatible assistants like Claude register, discover, and communicate with A2A agents. Supports stdio, streamable-http, and SSE transports. The repository was [**archived March 3, 2026**](https://github.com/GongRzhe/A2A-MCP-Server) (confirmed via its own archive banner), but the architectural pattern is increasingly relevant — mcp-gateway-registry has added A2A agent support and AWS Agent Registry Federation, and fast-agent now offers ACP (Agent Client Protocol) support via Zed, showing the ecosystem converging on multi-protocol interoperability.

## The Big Picture

Agent orchestration matured dramatically in the 27 days leading into the May 2026 update, and has kept moving since. Paperclip (57K→66K→~78K) and Ruflo (32.6K→48.2K→~68K) continue their explosive trajectories. Two significant new entrants arrived that update: open-multi-agent (now ~6.8K stars, minimalist TypeScript API) and microsoft/conductor (YAML deterministic routing with MCP tool support, now ~384 stars). And mcp-gateway-registry deepened its enterprise capabilities with AWS Registry Federation and Virtual MCP Server support.

**Highest momentum (as of the May 2026 update):** Ruflo (+48% in 27 days) was the fastest-growing project by percentage that period. Paperclip (+16%) had the highest absolute star count then, at 66K — both have grown well past those figures since. open-multi-agent's ~6.8K stars in a few months shows there's still room for new entrants with differentiated approaches.

**Production-ready workflows:** fast-agent (~3.9K stars, Agent Skills, ACP support) and the still-popular mcp-agent (~8.5K stars, Temporal backing) remain the most mature workflow frameworks — but mcp-agent's apparent pre-rewrite pause warrants monitoring before new production commitments. Paperclip (~78K stars, MIT) is production-ready for the organizational orchestration model.

**Massive scale:** Ruflo (~68K stars, ~314 MCP tools as of v3.5.59, agent federation) and Paperclip (~78K stars) represent the high end of ambition. Both require careful evaluation of which components you need.

**Deterministic control:** microsoft/conductor (YAML-declared topology, MIT, Microsoft-backed) fills a notable gap — reproducible, auditable workflows where the routing isn't up to an LLM. Pair with AWS CAO 2.0 (7 providers at launch, fewer/different now — see note above; Web UI) for a vendor-neutral CLI orchestration option.

**Enterprise infrastructure:** mcp-gateway-registry (~860 stars, AWS Registry Federation, 6 identity providers) now offers serious governance for MCP at scale.

**Key gaps narrowing:** Cost-aware scheduling addressed by Ruflo's 3-tier routing (vendor-claimed savings, not independently verified). Multi-provider support is now standard. Deterministic routing filled by microsoft/conductor. **Remaining gaps:** Standardized agent discovery across MCP, A2A, and ACP remains fragmented. Production observability across orchestrated agent networks is still limited. Task orchestrators and agent frameworks don't yet integrate well with each other.

**Archived projects:** awslabs/multi-agent-orchestrator (renamed Agent Squad → 2FastLabs), mcp-agentify (archived July 2026), EchoingVesper/mcp-task-orchestrator (Aug 2025), A2A-MCP-Server (March 2026) show the churn rate — ideas matter but maintenance is everything.

**Rating: 4.5/5** — Maintained. The category now has multiple projects well past 40K stars, multiple production-grade frameworks, new entrants at every level of abstraction (from Paperclip's company metaphor to open-multi-agent's three-dependency minimalism), serious enterprise infrastructure with AWS federation, and Microsoft's deterministic orchestration model. Protocol convergence (MCP + A2A + ACP) is accelerating.
